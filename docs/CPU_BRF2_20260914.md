# Two-sector branch refill buffer and deferred-redirect seeding (2026-09-14, candidate)

Built on the control-flow trim candidate's fifth version
(`CPU_CTRL_FLOW_20260914.md`); core only, scripts
`scratchpad/redir_seed.py` then `scratchpad/brf2.py`, tree
`/tmp/brf2-cand.*`.

## Why

The branch refill buffer holds one 32-byte sector: a taken branch whose
target words are all in the buffer refills the fetch queue from it with
no bus request (the DBcc/Bcc loop case, and since checkpoint 10 the
Bcc lookahead).  Two things limited it:

1. A redirect that cannot issue its fetch in its own cycle (a data
   acknowledge or a queue fetch owns the port) is issued by the fill
   engine a cycle later, and that fill carries no `epf_pend_seed`, so
   the target sector is never adopted.  Any loop whose back-branch is
   decoded while a speculative queue fetch is in flight, which is the
   common case, therefore never refills from the buffer.  The Sieve
   fixture's inner loop (`202c`-`203a`, 14,999 iterations) was one:
   its sector was never adopted, and each iteration fetched from memory.
2. With one sector, a loop straddling a sector boundary or containing
   two taken branches into different sectors evicts the buffer on every
   iteration.  Fixing (1) alone made this visible: the Sieve got slower
   at every offset (+6.5 K to +19.6 K cycles) because its outer loops
   alternate between two sectors.

## What changes

- `epf_redir_pend`: set by `issue_ifetch` when a redirect (not a refill
  hit) could not issue at once; the engine's next fill takes it as its
  `epf_pend_seed`, so the fill's line adopts the sector.
- Two sectors (`brf_data`/`brf_data1`, tags, supervisor bits, valid
  vectors) with a one-bit LRU: a refill hit, a same-sector append or a
  same-sector line offer makes its sector most recent; an adoption (a
  seeded fetch's acknowledge or its line offer) replaces the least
  recent sector.  `brf_m0`/`brf_m1`/`brf_vsel` do the compares;
  `brf_refill_hit`, the DBcc refill test, `issue_ifetch`'s seed count and
  `decode_dbcc_brf`'s first word all select the hit sector; the shared
  seed block reads the sector `brf_seed_sel` names.  A CPU write into
  either sector invalidates that sector; the architectural flush clears
  both.

## Results so far

- AP suite 11/11; corpus **30,250,757** cycles (**-10.3 %** against the
  33,723,250 baseline; the control-flow v5 base was 33,690,581), 0 REAL
  diffs; latency fixture 1,888 (v5: 1,904).
- Sieve sweep: **421,983 / 378,541 / 477,725 / 434,666** cycles at
  offsets 0/6/16/30 against 421,997 / 410,666 / 519,651 / 434,666
  (**-7.8 % and -8.1 %** at offsets 6 and 16, where the loops straddle a
  sector boundary; identical results).
- Boot A/B: 75,279,691 dispatches, no faults, the same frame as the
  16 KB cache candidate (second extension icon drawn).  Against the shift
  candidate's 75,280,762 the count is unchanged, but the profile moved:
  `S_FETCH` 30.80 M -> 27.12 M cycles (demand-fetch entries 5.53 M ->
  4.62 M), while `S_MRD` rose 146.4 M -> 148.1 M and `S_MWR` 38.0 M ->
  39.4 M (the control-flow trims move the RTS/UNLK/JSR/LINK stack
  accesses' cycles into those states and out of their own).  The
  Speedometer bracket decides.
- Simulated Speedometer running on the stacked build (this core plus the
  16 KB caches, `/tmp/stack-cand.*`), with a
  trimmed seed-20 fit (area: a second 256-bit sector, two more 27-bit
  tag compares, a 2:1 select ahead of the seed muxes).

### Stacked build (this core + 16 KB caches v2)

Tree `/tmp/stack-cand.*`: AP 11/11, corpus 30,265,733 (0 REAL diffs),
boot A/B 75,558,705 dispatches, no faults, same frame.  For reference in
the same 420 M-cycle boot bracket: shift candidate 75,280,762, +control
flow v5 75,469,718, +two-sector buffer 75,279,691, shift + 16 KB caches
75,584,400.  Simulated Speedometer and the seed 20 fit running.

### Fit: too large (parked)

The stacked build at seed 20 needed **41,495 ALMs (99 %)** against
39,132 for the same build without this core, and the router gave up:
the second sector roughly doubles the seed and first-word muxes (eight
16-bit words chosen from sixteen longwords, with the sector select on
top) and adds the tag compares, about 2,300 ALMs.  Parked.  The idea
that survives is the deferred-redirect seeding by itself; with a single
sector it thrashes two-sector loops (control-flow v4), so the buffer
would need a cheaper second sector (a sector kept in the fetch queue's
own ring, or the seed read narrowed to four words) before it can return.
The stack goes on without it (`/tmp/stack2-cand.*`: control-flow v5 core
plus the 16 KB caches v2).
