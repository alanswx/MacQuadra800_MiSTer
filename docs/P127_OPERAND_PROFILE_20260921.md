# P127 operand preparation profile and follow-up experiments

The instrumented original Dhrystone loop on P109/P120/P124 takes 114,804,374 loop cycles, unchanged from the uninstrumented baseline. Root verified all five capture files, all non-bench identity fields and the independent 50,000-iteration end-state checker. Evidence: `scratch/dhrystone_full_p127_profile_20260921`.

S_PIPE_START accounts for 13,500,218 cycles and S_PIPE_REGS for 7,000,009. Hot preparation opcodes include MOVEA.L d16(A6),A0 (1,750,062), ADDQ.L #1,d16(A6) (1,550,062), MOVE.B (A0),(A1)+ (1,550,062), CMP.B (A3),D0 (1,050,000), and MOVE.B (A2),D0 (1,050,000). Frequency identifies candidates; it does not establish a faster implementation.

P128 routes indirect CMP through the experimental pipeline. Its unapplied patch is `scripts/cpu/pipeline_indirect_compare.patch`, with isolated sources under `scratch/p128_indirect_compare_20260921`. Whetstone remains 27,949,845 loop clocks; Dhrystone is 115,854,373, a regression of 1,049,999 versus P120/P124. The initial agent comparison used the wrong baseline. Final output audit is pending; this experiment is not promoted.

P129 instead targets ordinary memory-to-memory MOVE preparation. After a successful source read reaches S_PIPE_SDONE, capture m_val and call the existing ea_start for the destination in the same cycle. This skips S_PIPE_DST while preserving the existing destination EA, register-update and store machinery. Guarded to ALU MOVE with memory source/destination, no RMW and no suppressed writeback. Core SHA256 200ee1d8e0b46a0963e107f220f3b5f322b27c654280b18933e7c25107361584; patch `scripts/cpu/move_destination_start.patch`, unapplied. Original workload screens are pending with explicit P120 pipeline and P124 cache. Correctness, precise faults, same-register postincrement/predecrement, interrupt replay, FPGA timing and hardware performance remain unproven.
